# NOVELIGHT Privacy Request Runbook

最終更新: 2026-09-27

## 目的

NOVELIGHTが受け付ける個人情報・保有個人データに関する請求を、本人確認・最小権限・記録保全を守りながら一貫して処理するための運用手順です。公開プライバシーポリシーと実装の食い違いを防ぐため、データ項目・委託先・請求経路を変更した場合は本書も見直します。

## 受付経路

原則として `contact.html` のお問い合わせフォームから受け付けます。主な種別は次のとおりです。

- 個人情報の開示・利用目的通知
- 個人情報の訂正・追加・削除
- 利用停止・消去・第三者提供停止
- 退会・アカウント削除
- その他のプライバシー相談

フォーム本文にパスワード、クレジットカード番号、本人確認書類を直接入力・添付させません。追加の本人確認が必要な場合は、請求内容に応じて必要最小限の方法を別途案内します。

## 初動

1. 問い合わせID、受信日時、返信先、請求種別を記録します。
2. 請求の対象が、本人のアカウント、先行作者登録、問い合わせ、決済・契約、読書・利用履歴等のどこに関係するか分類します。
3. 本人確認の要否・方法を決めます。既に認証済みアカウントと安全に照合できる場合は、不要な追加情報を求めません。
4. 請求対象と無関係な情報は探索・取得しません。

## 調査対象になり得るシステム

請求内容に応じ、必要な範囲で次を確認します。

- Supabase Auth: アカウント・認証情報
- Supabase Database: プロフィール、作品、読書進捗、本棚、流入・継続、先行作者登録、問い合わせ、決済・契約関連識別子等
- Stripe: 顧客・サブスクリプション・Checkout・支払状態等。NOVELIGHTがカード番号そのものを保存する設計ではないため、カード番号の開示・訂正等をNOVELIGHT側DBの対象として扱わない
- Resend: 先行利用案内・問い合わせ返信等の配送記録が請求対象に関係する場合
- Vercelその他のホスティングログ: 障害・不正・セキュリティ調査等で請求対象に関係する場合

委託先のデータを確認する必要がある場合でも、請求処理に必要な範囲を超えて取得しません。

## 請求別の処理

### 利用目的通知・開示

本人確認後、法令に定める範囲で対象情報と利用目的を特定します。第三者の権利、セキュリティ、不正対策、法令上の非開示事由に関係する情報は、そのまま返却しないことがあります。

### 訂正・追加・削除

事実と異なる情報や、利用目的上不要となった情報について対象を確認し、法令・契約・不正防止・セキュリティ・紛争対応上保持が必要な範囲を切り分けて処理します。

### 利用停止・消去・第三者提供停止

請求理由と法令上の要件を確認し、対象処理を停止・制限・消去する必要がある範囲を決めます。単にサービス提供に不可欠な委託処理を「第三者提供」と誤って扱わず、実際の処理関係を確認します。

### 退会・アカウント削除

削除前に、未解決の決済・返金・不正・権利侵害・法令保存・紛争対応の有無を確認します。保持根拠のないユーザーデータは削除または匿名化の対象とし、保持が必要なデータは目的外利用しないよう範囲を限定します。削除できない情報がある場合は、理由と対象範囲を整理して回答します。

## メール連絡の区分

現行のメール送信は、アカウント・セキュリティ・決済・先行利用案内・問い合わせ返信等の運営上必要な連絡を対象とします。β版先行作者登録の必須同意は「β版の公開・参加に関する連絡」のためのもので、一般的な広告・宣伝メールへの包括同意として再利用しません。

将来、広告・宣伝メールやニュースレターを実装する場合は、運営上必要な連絡とは分離し、適用法令に沿った同意取得・配信停止・同意記録を実装してから配信します。

## 回答・記録

- 対応内容、対象データ、本人確認方法、実施日時、実施者、回答内容を監査可能な形で記録します。
- 法令上の理由により全部または一部へ対応できない場合は、説明可能な範囲で理由を整理します。
- 本人確認情報を必要以上に保持しません。
- 問い合わせ対応を完了したら、必要に応じて問い合わせ状態を更新します。

## エスカレーション

次の場合は通常処理を止め、法務・個人情報保護の専門家への確認を検討します。

- 大量データ、第三者データ、権利侵害申告が混在する請求
- 国外移転・委託関係の法的評価が必要な請求
- 捜査機関・裁判所・行政機関からの正式な照会
- 漏えい等のインシデントと関連する請求
- 開示可否がセキュリティや第三者の権利へ重大な影響を与える場合

漏えい等が疑われる場合は `docs/SECURITY-INCIDENT-RESPONSE.md` を優先します。
