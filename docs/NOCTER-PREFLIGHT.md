# NOCTER PREFLIGHT

**ノクター公式素材 制作開始前チェック**

ノクターの画像生成・編集を開始する前に、毎回このチェックを通す。

## A. 作業開始ゲート

- [ ] NOVELIGHTの実作業として、全体と主要工程ごとの予想所要時間を先に提示した
- [ ] 10分を超える工程または外部待ちがある場合、待機要否と次工程への影響を説明した

## B. 公式参照の確認

- [ ] ノクター公式設定マスターシートを実画像として参照できる
- [ ] NOCTER IDENTITY LOCK SHEETを実画像として参照できる、または今回の最新Identity Lock参照4点を用意した
- [ ] 記憶や文章説明だけでノクターを再現しようとしていない
- [ ] 不採用画像・試作画像をキャラクターデザインの基準にしていない
- [ ] 顔基準に、小さな三面図の拡大ではなく大型公式原画から切り出した高精細顔資料を使える

## C. 今回の変更範囲

制作前に、今回変更してよいものを明示する。

例：

- 表情
- ポーズ
- 背景
- 季節
- 小道具
- 構図

それ以外は変更しない。

- [ ] 今回変更してよい項目を特定した
- [ ] 今回変更してはいけない項目を特定した

## D. Identity Lock項目

以下は原則固定する。

- [ ] 顔・輪郭
- [ ] 目の形・サイズ・配置・琥珀色
- [ ] 巨大な尖った耳
- [ ] 小柄な頭身・体型
- [ ] 黒〜濃紺の毛色と基本毛並み
- [ ] 金色の発光模様の位置・量
- [ ] 尻尾の形・ボリューム・発光
- [ ] 黒紺系マント
- [ ] 星型ペンダント
- [ ] 左側の金タグ

## E. 生成指示の禁止事項

- [ ] ノクターを再デザインしない旨を入れた
- [ ] 原画にない線・模様・装飾を追加しない旨を入れた
- [ ] 毛や装飾を豪華化しない旨を入れた
- [ ] 写実化・高精細化を理由にデフォルメ感を変えない旨を入れた
- [ ] 変更許可領域以外を維持する旨を入れた
- [ ] Identity Lock中は背景光・魔法粒子・火花・過度なブルーム等を抑える旨を入れた

固定補助文：

`If a marking, line, ornament, or accessory is not clearly present in the official reference, do not invent or add it.`

## F. 参照画像の絞り込み

通常の正面Identity Lockテストでは原則として、

1. 公式設定マスターシート
2. 三面図から切り出した正面全身
3. 大型公式原画から切り出した高精細な顔アップ
4. 公式ディテールから作った目＋耳の参照

の4点を中心にする。

NOCTER IDENTITY LOCK SHEETは補助基準として保持するが、上記4点と重複して生成側の解釈を増やす場合は機械的に追加しない。

- [ ] 無関係な参照画像を大量に与えていない
- [ ] 横向き・背面等の場合だけ必要な角度資料を追加している
- [ ] 装飾資料は頭部固定が完了する前に大量投入していない
- [ ] 顔アップは低解像度の正面全身を単純拡大した資料ではない

## G. Identity Lockの段階

Identity Lockは次の順で進める。

**第1段階：頭部固定**

- [ ] 顔の横幅・輪郭
- [ ] 頬毛
- [ ] 鼻〜口の距離
- [ ] 目の丸さ・大きさ・間隔
- [ ] 耳の幅・高さ・角度
- [ ] 頭頂部の毛・カール

**第2段階：シルエット固定**

- [ ] 頭身
- [ ] 胴体幅
- [ ] 前脚・後脚
- [ ] 全体シルエット
- [ ] 尻尾

**第3段階：装飾固定**

- [ ] マント
- [ ] 星型ペンダント
- [ ] 左側の金タグ
- [ ] 発光模様

- [ ] 第1段階が不合格のまま第2・第3段階を詰めようとしていない

## H. 二段階制作

可能な場合は、

**Identity Lock → Scene Edit**

の順で進める。

- [ ] まずキャラクター単体で同一性を確認できる
- [ ] 背景・演出を一発生成に混ぜず、後工程へ分離できるか検討した
- [ ] Identity Lock中の発光は公式模様を判別できる最低限に抑えている

## I. 生成AIと評価の分離

- [ ] 画像生成AIにはノクター本体の生成・編集だけを依頼している
- [ ] 比較表・採点表・QAシート・説明文・合否判定を同じ生成画像内へ作らせていない
- [ ] 公式原画との比較・差分抽出・採点は生成後の別工程で行う
- [ ] 画像内にAI自身が書いた点数・評価文を正式評価として採用していない

## J. 生成後採点

公式原画と比較して採点する。

| 項目 | 配点 |
| --- | ---: |
| 顔・輪郭 | 20 |
| 目 | 15 |
| 耳 | 15 |
| 頭身・体型 | 10 |
| 毛色・毛並み | 5 |
| 発光模様 | 10 |
| マント | 10 |
| ペンダント | 5 |
| 金タグ | 5 |
| 尻尾 | 5 |
| **合計** | **100** |

判定：

- **90点未満**：Scene Editへ進めない
- **90〜94点**：Scene Edit用の合格個体候補
- **95点以上**：基準個体候補。自動昇格はしない

## K. 修正ルール

- [ ] 公式原画との差分を具体的に列挙した
- [ ] 「もっと似せる」だけの全体再解釈指示にしていない
- [ ] 修正は1回につき1〜2種類の問題に絞る
- [ ] 既に合っている部位を変更しない領域として扱う
- [ ] 局所修正で済むのにキャラクター全体をゼロから再生成していない
- [ ] 修正後も再採点する

## L. 作業完了ゲート

- [ ] 参照資料の確認・切り出し・プロンプト準備だけで作業を終了していない
- [ ] 今回の目的が画像制作・編集である場合、原則として最低でも第1生成案または第1編集結果まで進めた
- [ ] 可能な場合は公式原画との差分を確認し、1〜2項目に絞った局所修正まで進めた
- [ ] 途中報告を行ったこと自体を作業終了理由にしていない

## M. 編集元固定・編集成立確認ゲート

既存のノクター画像を修正する場合は、新規生成と既存画像編集を明確に区別する。

- [ ] 「1個前」「さっきの画像」等の相対表現だけに頼らず、編集元となる画像を1枚に特定した
- [ ] 編集元のファイル、画像ID、生成ID等、利用可能な識別情報を確認した
- [ ] 編集元画像が画像編集ツールへ実際に読み込まれ、編集対象として結び付いていることを確認してから実行した
- [ ] 編集元の読み込み失敗・参照切れ・対象不明が発生した場合、新規生成へ自動的に切り替えていない
- [ ] 編集元を固定できない場合は、別キャラクター化する可能性があるため画像生成を繰り返さず、原因を解消してから再開した
- [ ] 修正許可項目を原則1〜2種類に限定し、それ以外を変更禁止領域として明示した
- [ ] 出力後、利用可能な場合は `parent_gen_id`、編集操作情報、その他の編集履歴を確認し、元画像との編集関係が成立していることを検証した
- [ ] 編集関係を確認できない出力を「局所編集成功」と報告していない
- [ ] 編集として成立していない出力は、見た目が良くてもIdentity Lock候補・基準個体・次回編集元として採用していない
- [ ] 現在のベスト個体を1枚に固定し、不採用画像・別キャラクター化した画像を次工程の編集元に使っていない

編集元固定に失敗した状態で再試行回数を増やしても、同一性は改善しない。まず編集経路を成立させ、その後に局所修正を行う。

## N. 変更禁止領域・実差分監査ゲート

既存ノクターの局所修正では、編集元が指定できていることだけで合格としない。出力後に、変更を許可していない領域が実際に保持されたかを必ず監査する。

- [ ] 実行前に「変更許可項目」と「変更禁止項目」を明示的に分けた
- [ ] 出力後、編集元画像と出力画像を見比べ、変更許可項目以外に意味のある変化がないか確認した
- [ ] 額・頬等の金模様、耳、口元、頭頂カール、マント、ペンダント、体型、尻尾その他の変更禁止項目が、許可なく追加・削除・変形・再解釈されていないことを確認した
- [ ] 指定した1〜2項目が改善していても、変更禁止領域に意味のある変化があればその出力を不採用とした
- [ ] 「全体として似ている」「前より綺麗」「雰囲気が近い」ことを、局所編集成立の根拠にしていない
- [ ] 利用可能な生成メタデータで `parent_gen_id` が空、`edit_op` が空、または同等に編集関係を確認できない場合、その出力を新規生成扱いとして即時不採用にした
- [ ] 編集成立を確認できない出力を採点対象・95点候補・ベスト個体・次回編集元に昇格させていない
- [ ] 同じ編集成立失敗が再発した場合、そのまま再生成を繰り返さず、編集元の再特定・再添付・参照経路の修復を先に行った

局所修正の合格条件は「目的箇所が良くなったこと」だけではない。「変更を許可していない領域が保持されたこと」と「元画像からの編集として成立したこと」の両方を満たして初めて合格とする。

## O. 直接アップロード編集元ゲート

既存ノクター画像の局所修正では、編集元画像を画像編集ツールへ確実に渡せることを最優先する。過去ターンの参照や内部保存パスだけで編集元が安定して結び付かない場合は、ユーザーが現在のチャットへ直接アップロードした画像を唯一の編集元として使う。

- [ ] 編集元は現在のチャットでユーザーが直接アップロードした画像、または現在ターンで明示的に編集対象として渡された画像に限定した
- [ ] 過去ターンの生成画像、「1個前」等の相対表現、内部保存パスだけを根拠に局所修正を実行していない
- [ ] 編集元が現在のチャット上で明示的に確定していない場合、画像生成を実行せず、まずユーザーへ対象画像の再アップロードを依頼した
- [ ] ユーザーが直接アップロードした編集元画像を、画像編集ツールが利用可能な入力として認識できることを確認してから実行した
- [ ] 直接アップロード画像を用いても編集元との関係を確認できない場合、新規生成で代用せず、その出力を不採用として編集経路の原因確認を優先した
- [ ] 一度直接アップロードされたベスト個体を今回の編集元として固定し、同一修正サイクル中に別の候補へ勝手に切り替えていない

このゲートの目的は、ユーザーに毎回不要な再アップロードを強いることではなく、過去参照や内部パスでは編集成立を保証できない状況で新規生成事故を防ぐことである。編集元との関係を別の方法で確実に検証できる場合は、その検証可能な経路を利用してよい。
