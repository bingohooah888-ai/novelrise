# NOVELIGHT SPECIAL（特別企画）機能仕様書 v1.0

作成日：2026年10月22日  
状態：**設計案／未実装／未公開**  
対象：NOVELIGHT公式サイト、運営管理画面  
目的：今後、複数の作家とのコラボ・特別掲載を継続的に追加し、読者をNOVELIGHTに呼び込むための共通基盤を先に構築する。

## 1. 最重要方針

1. **総合ページは常設**。「NOVELIGHT SPECIAL（特別企画）」をサイトの正式な導線にする。
2. **個別企画はデータ登録で増やす**。作家が増えるたびにHTMLやコードを書き換えない。
3. **掲載期間を強制しない**。開始日・終了日は任意。終了日が空なら自動終了しない。公開後も運営画面から期間・内容・順序・表示を変更できる。
4. **実際の企画は未契約の段階で公開しない**。作家名、作品名、表紙、参加実績などを仮の参加実績として出さない。
5. **既存機能を最大限再利用**。既存のヘッダー、テーマ、認証・運営権限、作品・エピソード閲覧、アクセス計測などを利用し、新たな閲覧エンジン・課金機能は作らない。
6. **読者は無料・会員登録不要**で企画紹介と許諾済み本文を閲覧できる。年齢確認など既存の必要な安全導線は維持する。
7. **評価の公平性を守る**。特別企画への有償出演を、通常作品のランキング順位、LIGHT SEED、SCOUT RECORD等の加点と結び付けない。
8. **著作権は権利者に残す**。有効な掲載許諾が確認された範囲の本文・画像・紹介文だけを公開する。
9. **開発対象はページと管理基盤に限定**。作家への営業、見積り、謝礼支払い、Xの自動投稿は今回実装しない。
10. **後から容易に変更できることを優先**。特定作家向けの固定デザイン・固定文言・期間限定前提の条件分岐を作らない。

## 2. ページ構成・URL

### 2.1 総合ページ

- 表示名：**NOVELIGHT SPECIAL／特別企画**
- 第一候補URL：`https://novelight.jp/special.html`
- 構成：共通ヘッダー → タイトル・短い説明 → 注目企画（任意） → 公開中の企画一覧 → その他の公開企画 → フッター。
- 企画カード表示：作家名、企画タイトル、作品名、画像（許諾がある場合のみ）、企画種別（SS／番外編／インタビュー等）、短い紹介文、詳細ページへのリンク。
- ソート：運営指定の表示順を基本とし、新着順への切替を設けてもよい。掲載期間が未設定の企画も通常表示。
- 絞り込み：初期版は「すべて／SS・番外編／インタビュー・その他」程度の最小構成。件数が増えた場合に拡張可能なデータ構造とする。
- 初回未掲載時：虚偽の作家カードを出さず「現在、特別企画を準備しています」と表示する。ページは公開可能。
- スマートフォンでの可読性、画像の遅延読み込み、画像欠損時の上品なプレースホルダーを必須とする。

### 2.2 個別企画ページ

- 推奨URL：`https://novelight.jp/special/{slug}`。既存のVercelルーティングとSEO実装を確認したうえで確定する。公開後のslug変更は原則禁止。
- 構成：企画タイトル、作家の正式表記・紹介、対象作品紹介、企画内容、特別SS等の閲覧導線、作家の希望する公式リンク、関連作品の案内。
- **メイン導線は「特別作品を無料で読む」**。本文がサイト内にある場合は既存のエピソード閲覧へ遷移。許諾が外部告知のみの場合は外部ページへ誘導。
- 本文以外の企画（インタビュー等）も扱えるように、コンテンツ種類を固定しない。
- 作品の複数話・複数SSに対応し、管理画面から掲載順を変更できる。
- リンクは、作家公式X、カクヨム等の既存掲載先、書籍・公式サイト等から任意に設定可能。外部リンクは安全なURLのみ。
- 有償タイアップ等、広告であることの明示が必要な企画には、タイトル近くに判別可能な「PR／タイアップ」表記を行う。
- 同一企画内の「ほかの作品を見る」欄やNOVELIGHTの通常作品への案内は、主役の作品を妨げない位置に置く。

### 2.3 サイト内の導線

- 公開サイトの共通ヘッダー（PC・モバイル）に「特別企画」リンクを追加。ただし既存ナビの折返し・押出し・ロゴ崩れを起こさない。
- トップページからも総合ページへ1クリックで到達できる導線を確保する。既存カルーセルの恒久占有は避け、掲載位置は設定で切替可能にする。
- 各個別企画から総合ページへ戻れる。
- 作者からXで案内された訪問者はログイン画面を挟まず目的の作品へ到達できる。

## 3. 運営管理画面

既存NOVELIGHT ADMIN内に「特別企画管理」を追加する。一般ユーザー・一般作者からは操作できない。

### 3.1 一覧画面

- 企画タイトル／作家名／公開状態／掲載開始・終了設定／更新日時／PV等を表示。
- 作成、編集、複製（下書きのみ）、プレビュー、公開、一時停止、再公開、終了、表示順変更を行える。
- 検索・公開状態フィルターを用意。

### 3.2 登録・編集項目

| 区分 | 主な項目 |
|---|---|
| 基本 | 管理ID、slug、企画タイトル、企画種別、短い説明、詳細説明、表示順、注目フラグ |
| 作家 | 表示名、プロフィール文、既存NOVELIGHT作者アカウントとの紐付け（任意）、公式リンク |
| 作品 | 対象作品名、紹介文、許諾済み画像、外部公式リンク、SS等の複数コンテンツ |
| 公開 | 下書き／公開待ち／公開中／一時停止／終了、任意の開始・終了日時 |
| 権利 | 掲載許諾の確認状態、利用許諾範囲、権利者名、許諾元、掲載条件、取り下げ条件、確認日、非公開管理メモ |
| 告知 | PR表記要否、公式X告知URL（任意）、流入計測用キャンペーン識別子 |
| SEO | 個別ページのtitle、description、OGP画像（許諾済みのみ） |

- 上記の未入力項目は、法的・公開上の必須項目を除き任意とする。
- **本文は管理画面から差替え可能**。既存作品・話の参照を使える場合は新規テキスト保存と二重化しない。
- 一般作者の有料プラン別投稿上限とは独立した「運営企画データ」とし、勝手に作家アカウントへ投稿した扱いにしない。
- 画像が未許諾の場合、画像欄を空欄にできる。通常小説のサムネイル生成ルールを無理に変更しない。

### 3.3 誤公開防止

- 企画を公開する条件：必須情報充足、掲載本文・画像の権利確認済み、公開確認操作。
- 未契約・許諾未確認は常に非公開。プレビューは管理者のみ。
- 権利期限が設定されている場合は期限を超えて本文を公開しない。終了日なしは掲載無期限を**保証する契約**を意味しない。
- 公開後の修正履歴（誰が・いつ・何を）を残す。本文・重要設定の変更前に復旧用のバージョンを保持する。
- 緊急非公開スイッチを備える。公開終了後の紹介ページを残すかどうかも権利条件に従って変更可能。

## 4. データ設計（実装時に既存DB構造へ適合させる）

- `special_projects`（または同等の既存テーブル）：企画メタデータ、作家情報、状態、表示順、公開日時、SEO、PRフラグ。
- `special_contents`：企画配下の作品・SS・インタビュー等、表示順、種類、既存作品/エピソード参照または許諾済み本文、公開状態。
- `special_permissions`：企画・素材ごとの権利許諾記録。添付契約・メール等の証跡は非公開ストレージに保存し、一般読者へ公開しない。
- `special_change_log`：公開・編集・非公開などの管理操作記録（既存監査ログが利用できるなら再利用）。
- 一貫した内部ID（UUID等）を採用。公開用slugは一意にして公開後は基本固定、リダイレクト可能な構造とする。
- Supabase RLS：一般閲覧者は公開許可かつ権利上公開可能なものだけ読み取り可。編集・削除・権利書類閲覧は運営管理権限のみ。ブラウザの表示・非表示だけに権限制御を依存させない。
- SQLや最終テーブル名は既存スキーマ確認後に決定。類似テーブルがあれば増設より再利用・最小拡張を優先。

## 5. 本文掲載・閲覧の扱い

- 許諾により「NOVELIGHT内全文掲載／既存NOVELIGHT作品へのリンク／外部掲載先へのリンク」を選べる。
- 本文をサイト内掲載する場合、原則として既存の小説・エピソード閲覧UIを利用し、基本の文字サイズ・縦横表示・読み上げ等の対応状況に合わせる。
- 企画用本文に関する通常作品ランキング、LIGHT SEED付与、SCOUT XP・称号、作者プランによる露出等の扱いは**自動混入させず別扱い**。通常作品に正式掲載する方式を使う場合だけ既存ルールとの整合を個別確認する。
- ユーザーによる自然な閲覧は計測するが、企画への謝礼をPV操作や高評価付与と結び付けない。
- R15・R18等の既存レーティング・安全表示を維持し、権利関係が不明な本文を保管・公開しない。

## 6. 集客・成果計測

- 企画総合ページUU・PV、個別企画UU・PV、SS閲覧開始／読了相当イベント、外部からの流入元（取得可能な範囲）、通常作品への遷移、作者公式リンクのクリックを測定。
- 企画別の計測用パラメータ（例：`utm_source=x&utm_medium=collab&utm_campaign={slug}`）に対応。ただしURLだけで特定作家の実投稿が行われたと断定しない。
- 管理画面の企画別簡易レポートで、閲覧 → SS読書 → NOVELIGHT他作品の閲覧の流れを確認できるようにする。
- 既存の分析・同意・プライバシー方針に準拠し、個人特定に不要な生ログ収集を増やさない。
- 検証可能なユーザー行動と推定値を区別する。

## 7. デザイン方針

- NOVELIGHTの黒紺・上品な金を基調とした既存ブランドを維持。文学的・高級感のある表現を優先し、派手な広告風にしない。
- PC・SP両対応、カードはスマホ1列・PC複数列。画像なしでも成立するレイアウト。
- 画像、作品名、作家名は権利者の許諾した素材・表記だけ使用。架空のコラボ実績を掲載しない。
- 「期間限定」「終了まであと○日」は、個別企画で運営が指定した場合にだけ表示。総合ページの基本仕様にはしない。
- 共通ヘッダー・フッター・アクセシビリティ対応を流用し、別ブランドの独立サイトのように作り直さない。

## 8. SEO・共有表示

- 総合ページと公開済み個別企画には適切なcanonical、title、description、OGP/Twitterカードを設定。
- 個別企画URLは直接アクセスやX共有で正しいタイトル・画像が表示されること。動的データをJavaScriptだけに依存させず、既存のサーバー側SEO配信方式を優先。
- 下書き・未許諾・停止中のページを検索エンジンに誤公開しない。
- サイトマップへ追加するのは公開可能なページのみ。個別企画の削除・変更では権利とSEOの両方を確認してリダイレクトまたは終了案内を選択。

## 9. 実施順序

**第1段階（今回先に作るもの）**

1. 最新main、MASTER、既存ページ・DB・RLS・管理画面を確認し、類似機能との重複を避ける。
2. 企画メタデータ・掲載権限を管理できる最小限のDB設計を実施。
3. 常設の総合ページを制作。未掲載でも破綻しない空状態にする。
4. 汎用の個別企画ページを制作。
5. 管理画面から企画を登録・編集・下書き保存・プレビュー・公開・停止できるようにする。
6. 共通ヘッダーとホームに破綻しないリンクを追加。
7. 基本SEOと既存解析への接続を行う。

**第2段階（最初の契約成立時）**

- 権利・素材確認 → 作家情報・SS等を登録 → 本番で内容を確認 → 公開 → 告知用URLを渡す。
- 既存SS、書き下ろし、インタビュー、外部リンクだけの企画を同じ仕組みで扱う。

**今回の対象外**

- 特定作家の参加確定を前提としたページ公開、作家への自動DM、報酬見積り・自動支払い、X自動投稿、新たなAI機能、既存ランキングの改変、新たな会員向け課金。
- 運営管理UIやSEOの細部は最小版を実装後、利用状況に応じ変更できるようにする。

## 10. 完了条件（受入テスト）

1. 公開前でも総合ページが正常表示され、架空の作家・作品を出さない。
2. 管理画面で新しい企画を**コード修正なし**に追加・編集できる。
3. 1人の作家に複数企画、1企画に複数コンテンツを登録できる。
4. 開始日・終了日の入力は任意。終了日なしで勝手に「期間限定」扱いにならない。
5. 公開後、文言・画像・掲載順・リンク・公開状態を管理画面から変更できる。
6. 許諾未確認では本文・画像が公開されない。取り下げ時は速やかに非公開化できる。
7. 一般読者は許諾済みページ・本文をログイン不要で読める。管理UIにはアクセスできない。
8. PC・スマホで共通ヘッダーやボタンがずれない。既存機能への回帰がない。
9. 公開した企画URLをX等で共有すると適切なOGP・説明が表示される。
10. 通常ランキング・LIGHT SEED・SCOUT RECORD・一般作者投稿上限・課金設定が企画追加で変化しない。
11. 公開・一時停止・終了の操作履歴が確認できる。未許諾の企画は検索結果・サイトマップに出ない。
12. 企画別の基本アクセス数と通常作品への遷移が確認できる。

## 11. 実装上の安全・コスト方針

- 本仕様書は**開発依頼の準備文書**。この文章の作成だけではDB変更・PR作成・公開を承認しない。
- 実装時は最新 `main`、`AGENTS.md`、`docs/NOVELIGHT-MASTER.md`、`docs/NLO-EXECUTION-POLICY.md` を優先する。
- DB・RLS・管理者権限・公開操作を含むため、既存のFULL PREFLIGHT／権限監査を適用する。
- Preview／Stagingは明示的な「ステージング承認」がない限り起動しない。本番反映も既存の承認手順に従う。
- 不要なVercelビルド、新規外部サービス、新規有料契約、重複データ管理を増やさない。
- 未コミット・未pushのローカル変更を破壊しない。関係のないリファクタリングは同梱しない。

**最終ゴール：** 最初の作家が決まった時点で、「作家情報・作品・許諾済み本文・公式リンクを運営画面から登録するだけ」でNOVELIGHT SPECIALに掲載でき、以後の作家追加も同じ運用を繰り返せる状態。
