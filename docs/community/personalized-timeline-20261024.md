# 2026-10-24 — みんなの交流：一本化と個人向け更新表示

## OWNER決定
ホームと交流広場は同一の新着順タイムラインを使う。従来の「みんな」「フォロー中」切替は撤廃する。

- 全利用者：新作公開、明示的な近況ノート共有、LIGHT SEED共有、おすすめリスト共有、公開済み公式お知らせ。
- ログイン済み利用者のみ：作者をフォローしている **または** 該当作品をお気に入り登録しているとき、その作品の第2話以降の公開も混在表示する。両条件が成立しても同一イベントを重複表示しない。
- 未ログイン利用者：第2話以降の更新は表示しない。
- 年齢区分、公開終了、ブロック／ミュート、非表示、運営モデレーション、作者ノート等の opt-in 条件はそのまま維持。
- 新規のエピソード公開は3時間単位でまとめない。1イベントにつき1投稿キーとする。既存3時間単位の投稿はいいね・コメント・共有URL保護のため変更しない。
- 作品のお気に入り・作者フォローは既存データを参照する。ランキング、PV、SCOUT、LIGHT SEED付与数へ影響させない。
- 公式お知らせは従来どおり一般タイムラインにも流す。専用お知らせページはそのまま残す。
- 掲示板は独立した機能として維持する。

## 技術上の注意

DBマイグレーションを適用した時点の `author_follow_events.id` 最大値を私有・RLS有効のシングルトンテーブルに固定。これ以前の更新は従来の3時間キーを維持し、その後の更新は `ep:<author-id>:<novel-id>:<1000000000000+event-id>` として新規採番する。利用者ごとのエピソード可視条件は、一覧だけでなく直接参照とリアクション/コメントにも適用する。

従来の `p_following` RPC引数は互換のため保持し、タイムライン表示には使用しない。ホームでも交流ページでも同じRPCを使う。

一括移行機能は **非公開下書きとして保存** するため、移行操作そのものは公開イベントを発生させない。今後、一括公開専用機能ができる場合は、その公開操作に対してイベント単位の集約契約を別途設ける（現在の3時間キー方式は復活させない）。

## リリース手順

1. 影響テスト、SQL構文・権限チェック、差分レビュー、CI。
2. Productionの`main`自動デプロイを起動するmergeには独立した本番承認が必要。
3. Production DBマイグレーションは、現在のmainのmigration一覧・Approval Ledger・本番承認を確認した正規workflowのみで適用する。
4. DB適用直前には、古いfrontendで「フォロー中」だけに意味がある表示が残る可能性があるため、切替順・互換性を確認。公開中のユーザーデータを変更しない。
5. 確認：未ログインでは更新投稿ゼロ、フォロー／お気に入り／両方／どちらもなし、R18と非公開、過去投稿リンク、直接コメント、掲示板、公式avatar、ページング。
