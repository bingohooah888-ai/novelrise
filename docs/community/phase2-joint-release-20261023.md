# NOVELIGHT 交流広場 — タイムライン・掲示板セット公開仕様（2026-10-23）

## 運営の更新決定

2026-10-23、OWNERは「タイムラインと掲示板はセットだから同時に公開したい」と指定。従前の「タイムラインを先に公開→原則2週間観察→掲示板をPhase 2として公開」は日程・公開順序に限って撤回する。Phase 1実装は破棄しない。

- タイムラインは2026-10-23に一度Productionへ公開されたが、同日に保護された既存OWNER実行で `public.community_runtime_control.public_enabled=false`、`activated_at=null` を確認。機能データは保持。
- 掲示板が安全に完成するまで、両機能を非公開に保ち、ヘッダーの交流導線を隠し、直接 `community.html` で準備中と表示する。
- リリース日にタイムライン・掲示板の **UIスイッチ2つ** と **Production側の有効化条件** をすべて成立させる。単一スイッチだけを先行公開しない。
- 掲示板の実装・レビュー・承認と、Production migration・Vercel deployment・DB runtime activation は別々の保護された工程。事後読み取り検査を実施。公開前の実ブラウザ認証3役検証はOWNER判断により公開後へ延期。既存のNode/RLS/模擬ブラウザ/CodeQLを省略する意味ではない。

## 既に採用された掲示板の範囲

### 構造

単一の掲示板を、次の3カテゴリで区分する。

1. 雑談・自己紹介
2. 創作相談・情報交換
3. おすすめ作品・読書トーク

各スレッドはカテゴリを1つ必須で指定し、作品ジャンルタグを任意に設定できる。トップでカテゴリ・新着・注目を切り替え、キーワード検索と並び替えを可能とする。カテゴリや注目表示に課金・Rank・SCOUTの影響を混ぜない。

### 利用権限と操作

- 未ログイン利用者：公開対象スレッドと返信を**閲覧可能**。非公開、削除、制限対象は不可。
- ログイン利用者：スレッドを作成、返信、いいね、本人の投稿/返信の編集・削除、通報・ブロックが可能。
- **新規スレッド作成は1人1日3件まで**。不正連続投稿対策と連動し、サーバ側で強制する。返信にも適切な短時間レート制限を設定する。
- スレッドには任意で **公開中作品の作品カード1件** を添付できる。未公開・削除・R18作品の一般掲示板露出は禁止。後から非公開化された場合はカードを自動的に非表示とする。
- 通知は本人向けに限定し、スレッドへの返信等に対応。既存通知との識別、本人以外の通知閲覧防止、既読処理の権限確認を行う。
- 掲示板全文をタイムラインへ自動流入させない。運営が選定し条件を満たす「注目の掲示板スレッド」の紹介のみを専用形式で掲載できる。全文転載せず、安全なリンクで誘導。

### 安全とモデレーション

- R15は全年齢向けと明確に区別し、R18対象を一般掲示板や一般タイムラインへ混ぜない。年齢・公開状態の既存ルールを破らない。
- 直接テーブルへの `anon`/`authenticated` 読書き権限は原則付与しない。露出用の安全なRPC等を通し、サーバ側で公開状態・本人確認・所有者ID検証・block/muteを適用する。
- 運営は通報確認、スレッド/返信の非表示・復元、悪質ユーザーの投稿制限、判断履歴の確認ができる。運営のみ操作可能なサーバ側権限が必要。利用者本人には他人の投稿操作・報告データアクセスを許さない。
- 一般公開の停止スイッチはDB側で保ち、問題時にはまずOFFにできる。既存データ消去やPR強制ロールバックを停止手段にしない。
- 掲示板の閲覧・いいね・返信を作品のRank、LIGHT SEED、SCOUT XP/Point、PV、お気に入り、作品発見順位、LIGHT ANALYTICSへの加点・操作信号にしない。個別作品に誘導した後の通常閲覧だけ既存読書計測契約に従う。

## データ・移行・テストの受け入れ条件

- Phase 1の `community_runtime_control`、既存の作品・近況ノート・ユーザー・作者データを変更・削除しない。
- Phase 2専用スレッド、返信、反応、通報・モデレーション、通知の保存境界は、レビュー可能な **新規のversioned migration** として管理。既存の適用済み `20261014052000` を書き換えない。
- 投稿者以外の編集/削除不可、匿名アクセスの非公開漏出なし、ブロック・ミュート、スレッド通報、通知IDOR、レート制限、年齢区分、作品カード状態変化のRLS/RPC契約試験を追加。
- PC/スマホで掲示板閲覧・スレッド作成・返信・検索・カテゴリ切替・管理・エラー状態を模擬E2Eで確認。
- Productionは「Phase 2 migrationが正常適用」「掲示板モデレーション導線あり」「ヘッダー/タイムライン/掲示板ともリリース状態」「公開後の停止経路あり」が成立するまではDB `public_enabled=false` を維持する。
- 掲示板Phase 2実装完了後、二機能同時公開の別承認を取得し、既存承認台帳とGitHub保護ワークフローを使う。実ブラウザによる本番運用確認は公開後に実施する。
