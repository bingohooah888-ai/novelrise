# NOVELIGHT Security Incident Response

最終更新: 2026-09-27

## 目的

個人データの漏えい、滅失、毀損、不正アクセス、認証情報の侵害、誤公開その他のセキュリティ事故またはその疑いが発生した際に、被害拡大防止・証拠保全・影響評価・法令対応・復旧を一貫して行うための手順です。

本書は公開用の詳細な防御設計書ではありません。秘密情報、具体的な認証情報、攻撃に悪用できる構成情報は記録しません。

## 1. 検知・受付

事故または疑いを検知したら、次を記録します。

- 検知日時と検知経路
- 対象サービス・機能
- 現時点で分かる事象
- 影響が疑われるデータ種別
- 継続中か停止済みか
- 初動担当者

確証がなくても、個人データや認証・決済・権限境界に関係する可能性があればインシデントとして扱います。

## 2. 封じ込め

被害拡大を防ぐため、影響範囲に応じて必要最小限の措置を行います。

- 問題のある公開経路・RPC・API・機能の停止または制限
- 漏えいした可能性のあるキー・トークン・セッション・認証情報の失効またはローテーション
- 誤った権限・RLS・公開設定の修正
- 不正アカウント・不正操作の一時停止
- 必要に応じたリリース停止

Production変更は、緊急性と既存のProduction approval / deployment contractを踏まえ、可能な限り監査可能な経路で行います。緊急封じ込めを優先した場合も、事後に必ず操作記録を残します。

## 3. 証拠保全

原因調査に必要なログ、監査記録、関連コミット、デプロイ、設定変更、問い合わせ等を保全します。証拠保全のために不要な個人データを新たに複製しません。

既存ログの削除・改変につながる作業は、調査に必要な証拠を確保してから行います。

## 4. 影響範囲の確定

最低限、次を確認します。

- 対象となったデータの種類
- 対象利用者数または概算
- 発生・露出していた期間
- 外部から実際に取得・閲覧・改変された証拠の有無
- 認証情報、決済関連情報、作品非公開情報、問い合わせ内容等の機微性
- 再現可能性と現在の封じ込め状態
- 委託先（Supabase、Vercel、Stripe、Resend等）が関係するか

推測と確認済み事実を混同しません。

## 5. 法令上の報告・本人通知の判定

個人情報保護委員会への報告や本人通知が必要となる事態に該当するか、事故の種類・影響・件数・不正利用のおそれ等を確認して判定します。

判断に迷う場合や重大な事故は、個人情報保護・法務の専門家へ速やかに確認します。

参考: 個人情報保護委員会「漏えい等報告・本人通知の義務化について」
https://www.ppc.go.jp/news/kaiseihou_feature/roueitouhoukoku_gimuka/

報告・通知が必要な場合は、法令上求められる期限・項目・方法をその時点の公的情報で再確認します。本書に固定期限をハードコードしません。

## 6. 利用者への連絡

本人通知その他の連絡を行う場合は、確認済みの事実に基づき、少なくとも次を明確にします。

- 何が起きたか
- 影響した可能性のある情報
- NOVELIGHTが実施した封じ込め・復旧
- 利用者に必要な対応があるか
- 問い合わせ窓口

原因が未確定の内容を断定せず、不必要に秘密情報や攻撃手順を公開しません。

## 7. 復旧・再発防止

修正後は、影響した境界の再テスト、権限・RLS・API・ログ・監視の確認を行い、必要に応じてCIのcontract testやリリースゲートへ再発防止策を追加します。

Production復旧後も一定期間、関連ログ・エラー・不正アクセス兆候を重点的に監視します。

## 8. 事後レビュー

インシデント終了後、次を記録します。

- 根本原因
- タイムライン
- 影響範囲
- 実施した封じ込め・復旧
- 報告・本人通知の判断と根拠
- 再発防止策
- 未完了のフォローアップ

個人データの取扱いそのものに変更が生じた場合は、`privacy.html`、`docs/PRIVACY-REQUEST-RUNBOOK.md`、関連する利用規約・運用文書・テストも見直します。
