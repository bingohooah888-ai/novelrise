## 1. サービス概要

NOVELIGHTは、日本語圏を主対象としてβ開始を予定する小説投稿プラットフォームです。

基本思想は、知名度や既存ファン数によって作品が評価前に埋もれる「機会格差」を減らすことです。

有料プランで販売する中心価値は、

- 作品が読者の目に触れる**追加の発見機会**
- 作者向けの分析機能

であり、

- 高評価
- ランキング順位
- 読者数
- 売上
- 出版・書籍化

等の成果そのものを保証・販売する設計ではありません。

読者には基本的に課金せず、作者向けにFree / Standard / Premiumを提供する設計です。

## 2. 現在の料金・契約モデル

| プラン | 月額 | 主な位置づけ |
| --- | ---: | --- |
| Free | 0円 | 1作品、一般発見枠、新作初期露出、基本分析 |
| Standard | 980円 | 10作品、一般枠とは別の追加露出、分析 |
| Premium | 1,980円 | 30作品、より多い追加露出、Premium専用追加露出、新作48時間ブースト等 |

有料プランは月額の継続契約です。

現在の実装ではStripeを利用し、

1. NOVELIGHT料金画面
2. Stripe hosted Checkout
3. 契約状態反映
4. Stripe Customer Portalによる契約管理・解約

という流れを採用しています。

クレジットカード番号そのものをNOVELIGHTのDBへ保存する設計ではありません。

公開文書:

- `pricing.html`
- `billing-policy.html`
- `commerce-disclosure.html`
- `terms.html`

### レビューしてほしい点

- Stripe hosted Checkoutを含む全体フローが、定期購入の申込み最終確認として日本の表示要件を満たすか。
- 月額、更新周期、次回請求、解約方法、解約効果、返金条件、提供時期等の表示の位置・タイミングが十分か。
- Stripe側表示へ依存してよい事項と、NOVELIGHT側で明示すべき事項の境界。

## 3. 特定商取引法に基づく表記の現在案

`commerce-disclosure.html` を公開しています。

現在、以下はウェブ上で直接表示せず、請求時に遅滞なく提供する方式を採用するドラフトです。

- 販売業者・役務提供事業者
- 運営責任者
- 所在地
- 電話番号

請求導線として `contact.html` に

`特定商取引法に基づく表示事項の開示請求`

という専用の問い合わせ種別を設けています。

運用上は新規問い合わせを自動監視し、法務・課金系を優先するRunbookがあります。

### レビューしてほしい点

- NOVELIGHTの実際の事業形態・販売方法で、上記の請求時開示方式を採用できるか。
- 表示省略を行う場合の文言・場所・請求手段・回答速度が十分か。
- 運営者が弁護士へ非公開で提示すべき正確な氏名/名称、住所、電話番号の要件。
- Stripe側が日本の加盟店へ要求するCommercial Disclosureとの整合。

## 4. 利用規約・UGC・作者の権利

`terms.html` では、投稿作品の著作権その他の権利は投稿によってNOVELIGHTへ移転しない方針です。

サービス提供、表示、検索、推薦、告知、バックアップ、不正・権利侵害対応等に必要な範囲で、NOVELIGHTへ非独占的な利用許諾を与える構成です。

禁止事項には、盗作・無断転載・権利侵害、なりすまし、嫌がらせ、不正なPV/評価/露出操作等を含めています。

通報機能と運営確認フローを設けています。

### レビューしてほしい点

- 投稿作品の利用許諾範囲が過不足ないか。
- 作者による権利保証条項の表現。
- 通報・非公開化・削除・アカウント停止等の運営権限。
- 著作権侵害申告、削除対応、証拠保存、異議申立て等でβ前に追加すべき手続き。
- UGCプラットフォーム運営者として追加で明記すべき事項。

## 5. 免責・責任制限・サービス変更

NOVELIGHTは、有料プランを含めて成果を保証しない方針です。

現行規約には、

- 特定の露出量
- ランキング順位
- 読者獲得
- 収益
- 出版

等を保証しない旨があります。

故意・重過失や法令上免責できない場合を除外する文言も置いています。

### レビューしてほしい点

- 消費者契約法を含め、現在の免責・責任制限が適切か。
- 有料の「追加露出」を販売する際に、最低限保証すべき内容・説明すべき計測誤差・停止時対応。
- サービス/料金/露出ロジック変更条項の妥当性。
- 障害、外部サービス障害、データ消失等の責任条項。

## 6. 解約・返金

`billing-policy.html` の現在案では、利用者都合による契約期間途中の返金・日割り返金は原則行わず、法令上必要な場合、重複請求、NOVELIGHT側の重大な決済障害等を例外として扱っています。

課金・解約・返金・重複請求等は `contact.html` の「課金・解約」窓口へ誘導しています。

### レビューしてほしい点

- 「原則返金なし」の文言と例外が適切か。
- 消費者契約法・特商法その他の強行規定との関係。
- 解約の効力発生日、期間末までの利用、日割り、誤請求・重複請求の扱い。
- Stripe Portalの表示とNOVELIGHT文書に矛盾が生じた場合の扱い。

## 7. 未成年者

現行規約・プライバシーポリシーでは、未成年者について必要に応じて法定代理人の同意を得ること、有料契約を法定代理人の同意なく行わないことを記載しています。

### レビューしてほしい点

- β版で想定すべき最低年齢や年齢確認の要否。
- 無料利用と有料契約で必要な同意設計。
- 未成年者取消しリスクに対する申込画面・規約・運用上の対策。
- 成人向け/成熟テーマのゾーニングとの関係。

## 8. 投稿コンテンツ・成熟表現・Stripe制約

β版の現在方針:

- 性的満足を主目的とする露骨な性的・ポルノグラフィックコンテンツは禁止。
- それ以外の成熟テーマを一律禁止にはせず、内容警告・年齢/内容注意等でゾーニングする。
- 法令、Stripe、ホスティング等の外部規約がより厳しい場合は外部要件を優先する。

`content-guidelines.html` とMASTERで整合させる方針です。

### レビューしてほしい点

- 日本法上、投稿サイトとしてβ前に明確化すべき禁止カテゴリ・年齢区分。
- 青少年保護、わいせつ表現、違法情報等に関する運営上の最低要件。
- Stripeのコンテンツ制約とNOVELIGHTのゾーニング方針を両立させる公開文言。

## 9. AI利用作品

NOVELIGHTはAI創作を一律禁止しません。

現在は、AI利用区分の申告、投稿ガイドライン、不正対策等を行う設計です。

AI判定だけを根拠とした原則自動BAN・自動削除は行わず、異常検知と人間の運営確認を組み合わせる方針です。

### レビューしてほしい点

- AI生成/AI補助作品の申告項目・表示方法。
- 著作権・第三者権利・類似性・学習元に関する投稿者保証の不足。
- AI利用に関する規約・ガイドライン上の責任分界。

## 11. 問い合わせ・通報・運営体制

`contact.html` は、

- 特商法表示事項の開示請求
- 課金・解約
- 投稿・作品
- プライバシー
- 不具合

法務・課金・安全関連を優先する運用です。

### レビューしてほしい点

- 特商法開示請求に対する実際の回答期限/目安と運用。
- 権利侵害・プライバシー・削除依頼等の本人確認方法。
- 問い合わせ記録の保存期間。
- β初期の運営監視頻度が十分か。

## 12. 技術的に確認済みの主な事実

以下は法的評価ではなく、公開β判断用の技術証拠です。

- Supabase productionでβ用migrationを適用し、read-only production verificationを運用。
- Supabase Proのscheduled daily backupを確認し、7日保持を記録。
- 非productionプロジェクトへのrestore rehearsalを実施済み。
- 隔離Stagingで認証済みproduct smokeを実施。
- LIGHT ANALYTICSの基本ファネルを、表示→作品詳細→第1話10秒読書→第2話継続→お気に入りまで実ブラウザで検証。
- 隔離Staging + Stripe test modeで、Checkout→Standard権限→Billing Portal→解約→Staging契約状態再同期を実ブラウザで検証。
- 一時Stagingテストデータのcleanupを自動化。
- productionとStagingのSupabaseを自動ゲートで分離。

### 重要な未検証境界

保護されたStaging Previewでは、Stripeの外部Webhook配送そのものをproduction相当の方法で証明していません。

Staging課金E2Eは安全なStaging専用reconciliation経路を使用しています。

したがって、

**外部Stripe → Production Vercel webhook endpoint → Production Supabase**

の実配送は、public betaでproduction課金を信頼する前の別技術ゲートとして残っています。

## 13. 弁護士に確認をお願いしたい優先順位

### P0 — 公開前に回答が必要

1. 特商法の氏名/名称・住所・電話番号の請求時開示方式
2. Stripe Checkoutを含む定期購入の最終確認表示
3. 返金・解約・自動更新条項
4. 消費者契約法を含む免責/責任制限
5. 未成年者の有料契約
6. APPI/privacyの重要不足
7. UGC/著作権・削除/通報の重大不足

### P1 — β初期に修正期限を設定できるものがあれば分類してほしい

- 法務文書の表現改善
- 問い合わせ/本人確認運用
- 保存期間の具体化
- 成熟コンテンツのゾーニング詳細
- AI作品の追加表示・保証条項

### 希望するレビュー成果物

可能であれば各指摘を、

- `BLOCKER`: public beta前に必須
- `HIGH`: β前を強く推奨
- `MEDIUM`: controlled beta中に修正可
- `LOW`: 将来改善

の4段階で分類してください。

また、修正が必要な場合は、対象ファイル/条項と推奨文言または要件を示していただけると実装へ反映しやすくなります。
