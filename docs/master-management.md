# NOVELIGHT MASTER 管理手順

`docs/NOVELIGHT-MASTER.md` をNOVELIGHTの唯一の正式な正本（Single Source of Truth）として扱う。

## 通常更新

1. `main` の最新 `docs/NOVELIGHT-MASTER.md` を取得し、全文を確認する。
2. 過去コピーやバックアップを更新元にしない。
3. 原則として必要箇所だけを差分追記・差分修正する。
4. 新しい方針の追加を理由に、無関係な既存方針を削除しない。
5. 更新前後のdiffを確認し、意図しない削除、章欠落、大幅な縮小がないことを確認する。
6. `npm test` を実行し、MASTER integrity testを通す。
7. Pull Request上でも変更差分を確認してからmergeする。

## 大幅変更・削除

既存方針、機能、決定事項を削除または大幅変更する場合は、ユーザーがその変更を明確に決定した場合に限る。

通常更新で大幅な削除が発生した場合は作業ミスを疑い、先に正本とバックアップを照合する。

## 復旧

MASTERの欠落・巻き戻しを発見した場合、単一の過去版をそのまま復元しない。

次を時系列で照合する。

- GitHub上の正本履歴
- 保存済みMASTERバックアップ
- バックアップ以後に確定した戦略・仕様・名称・法務方針

復旧後は、重要項目・章構造・文書量を自動テストで確認し、同じ欠落が再発しないよう保護アンカーも更新する。

## 自動保護

`tests/master-integrity.test.js` は既存の `npm test` と必須CI `check` に含まれる。

以下を自動検知する。

- 重要な戦略・機能・原則の欠落
- 章番号の欠落・重複・逆転
- MASTER全体の異常な短縮
- 正本保護原則そのものの欠落

自動検査は内容の妥当性を完全に保証するものではない。必ずdiffレビューと併用する。
